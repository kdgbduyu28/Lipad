# Lipad Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web-first flight search + trip budget planner for Filipino travelers, on free APIs, deployed to Cloudflare Pages.

**Architecture:** Expo Router app (web static export) talks only to `/api/*` Cloudflare Pages Functions. The functions call the Travelpayouts Data API with the secret token, cache answers 2 h with the Cache API, and fall back to labeled sample fares when no token is set. Pure logic (fares, planner, booking links, formatting) lives in `src/lib` with vitest tests.

**Tech Stack:** Expo SDK 57, expo-router, React Native Web, TypeScript, zustand + AsyncStorage persist, vitest, Cloudflare Pages Functions.

**Spec:** `docs/superpowers/specs/2026-11-20-lipad-design.md`

## Global Constraints

- Free APIs only: Travelpayouts Data API (token), Travelpayouts data files, Frankfurter, Open-Meteo.
- `TP_TOKEN`, `TP_MARKER` only in Pages env; never in the bundle.
- Every price shows its age ("checked 2h ago") and "final price on the booking site".
- Group total: adults + kids at adult fare, infants at 10%, labeled "estimate".
- Book sheet order: airline site → Trip.com → Aviasales fallback.
- English + Filipino via `t()`; light/dark/system theme; works at 375 px and desktop (max content width 960).
- Own look and name; no Skyscanner/CheapOair branding.
- Per the user's standing rule, tests are written as we go and run once at the end, before deploy.

## Review Focus

1. **No prices for a route** (Data API only has recently searched routes) → friendly empty state with "try the whole month / nearby airports", never a blank screen. Test: `normaliseFares([])` → `[]` and results screen empty state.
2. **Same origin and destination, or return before departure** → search button disabled with a reason. Test: `validateSearch`.
3. **API down / no token** → sample fares clearly badged "Sample prices", app still usable. Test: function returns `{ sample: true }`.
4. **Budget below every option** → planner says "Nothing fits ₱X yet" and shows the closest 3 with how much more is needed. Test: `planTrips` returns `fits:false` rows sorted by shortfall.
5. **Unknown airline code in airline-link config** → falls back to the airline's homepage or skips to Trip.com. Test: `bookingOptions` with unknown code.
